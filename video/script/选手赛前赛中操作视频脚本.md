# 选手赛前、赛中操作说明视频脚本

## 一、视频定位

- 视频名称：2026 年江苏省生态环境监测技能竞赛排污单位自行监测质量 AI 核查赛道选手操作说明
- 适用对象：本赛道全体参赛选手
- 视频目的：说明选手在赛前测试和正式比赛期间应完成的准备、系统接入、答题、保存、提交及异常报告操作
- 建议时长：16 至 18 分钟，配音后按清晰语速微调镜头停留时间
- 建议画幅：1920 × 1080，16:9
- 表达方式：界面录屏为主，必要时配合简洁的步骤标题、局部放大和鼠标高亮
- 语言要求：使用普通话，语速平稳，措辞正式，不使用网络化、口语化表达

> 本视频用于说明系统操作。具体比赛时间、地点、网络接入方式、账号发放、允许软件范围和现场管理要求，以正式竞赛指南及组委会最新通知为准。

## 二、统一用语

视频中应统一使用以下名称，避免概念混淆：

- “登录账号”和“登录密码”：用于登录在线答题系统。
- “API URL”：用于在本地知识库或智能化工具中配置模型服务地址。
- “API Key”：用于调用竞赛模型服务，不是网页登录密码。
- “模型 ID”：模型调用时填写的准确标识，必须以系统页面显示内容为准，并严格区分大小写。
- “保存草稿”：将当前答案保存到服务器，保存后仍可继续修改。
- “本机缓存”：浏览器在当前电脑中保留的异常恢复副本，不能替代服务器草稿。
- “最终提交”：按题执行的正式交卷操作。每道题最终提交成功后立即锁定，不能再次修改或撤回。

## 三、全片结构

1. 开场及操作流程概览
2. 赛前设备与离线环境检查
3. 赛前建立并检查本地知识库
4. 登录赛前测试环境
5. 配置并测试模型 API
6. 完成一次全流程赛前演练
7. 正式比赛现场接入与登录
8. 接收题目并确认作答要求
9. 使用本地知识库和允许模型开展分析
10. 编辑答案、上传附件和保存草稿
11. 恢复本机未保存答案
12. 逐题检查并最终提交
13. 异常情况处理
14. 结束提示

**屏幕文字：**

> 建议配置：内存不低于 16GB，可用磁盘空间不低于 100GB<br>

**旁白：**

> 首先准备比赛电脑和必要配件。请准备本人比赛电脑、电源，以及必要的鼠标、键盘、有线网卡或转接器。建议电脑内存不低于十六 GB，可用磁盘空间不低于一百 GB。上述配置属于赛前准备建议，不作为评分条件。没有原生有线网络接口的电脑，应提前准备兼容可靠的 USB 或 Type-C 转接器，并完成驱动和连接测试。为减少现场无线信号干扰，建议使用有线鼠标和键盘。

**录制验收点：**

- 将“建议配置”和“评分条件”明确区分。
- 不提前假定现场接口形式，补充“以组委会最新通知为准”。

**建议时长：** 02:00 至 02:45

**画面：**

- 先关闭无线网络，示意电脑处于无外网状态。
- 依次启动参赛软件、本地知识库和文档工具。
- 展示本地知识库能够正常打开，已有资料能够检索。

**屏幕文字：**

> 参赛软件、本地知识库和所需规范资料应提前保存在本机<br>
> 断开外网后仍应能够正常启动和检索

**旁白：**

> 正式比赛网络与外网物理隔离，因此参赛软件、本地知识库和所需规范资料都应提前保存在本机。知识库内容和工具由选手自行准备。赛前应主动断开外网，完整启动参赛软件和本地知识库，确认软件可以启动，资料可以索引和检索。不得把必须在线安装、在线登录或在线授权的步骤留到比赛现场。

**录制验收点：**

- 录制画面不得出现选手个人邮箱、商业软件授权信息或无关文件。
- 明确离线测试应覆盖“启动、索引、检索、引用”全过程。

**建议时长：** 02:45 至 03:50

**画面：**

- 展示本地知识库中的资料分类，例如管理规定、行业技术指南、手工监测规范、自动监测规范和监督检查规程。
- 输入一个模拟检索问题。
- 展示检索结果中的原文片段、文件名称、版本信息和条款位置。

**屏幕文字：**

> 检索结果至少应便于核对：原文、文件名称、版本信息、条款位置

**旁白：**

> 本地知识库用于存储和检索排污单位自行监测监督检查相关资料。知识库内容应覆盖管理规定、行业自行监测技术指南、手工和自动监测技术标准规范，以及监督检查技术指南和规程等文件。检索结果应尽量同时返回原文、文件名称、版本信息和可定位条款，以便在比赛中快速回到规范原文进行核验。知识库可以使用选手熟悉的工具搭建，但必须能够快速更换模型服务地址、API Key 和模型 ID，不得把公网地址或单一模型名称写死在程序中。

**屏幕文字强调：**

> AI 输出仅用于辅助核查<br>
> 最终结论必须回到原始材料和规范原文进行人工复核

**旁白续：**

> 需要特别说明，模型输出只用于辅助分析，不能替代选手判断。所有问题、依据和结论，都应对照企业档案原始材料和现行有效的规范原文进行人工复核。不得伪造引用，不得使用与本场材料无关的预制结论。

**录制验收点：**

- 模拟资料应使用公开或专门制作的演示文件。
- 检索画面必须能看出引用来源，而不是只展示模型生成结果。

### 镜头 08：复制 API URL、API Key 和模型 ID

**建议时长：** 05:00 至 06:10

**画面操作：**

1. 在“模型 API 技术文档”顶部高亮 API URL。
2. 点击 API URL 右侧复制按钮。
3. 高亮 API Key，点击复制按钮，但在成片中对具体值打码。
4. 向下展示“可用模型”表格中的模型 ID、模型名称、支持输入、上下文窗口和说明。
5. 选择一个模型，点击对应的“复制模型 ID”按钮。

**屏幕文字：**

> API URL 已包含 `/v1`，不得重复拼接<br>
> 模型 ID 应直接复制，并严格区分大小写

**旁白：**

> API 技术文档顶部显示本人专属的 API URL 和 API Key。配置本地知识库时，应复制完整的 API URL。该地址已经包含 `/v1`，不得再次重复拼接。API Key 应填写到工具的模型服务凭证位置，调用时使用 `Authorization: Bearer API_KEY`。下方“可用模型”表格列出了当前允许调用的模型。模型调用必须使用页面显示的准确模型 ID，并严格区分大小写。为避免输入错误，建议直接使用每行右侧的复制按钮。最终允许使用的模型，以比赛现场系统页面显示的列表为准。

**安全提示画面：**

> API Key 仅限本人、本场比赛使用<br>
> 不得共享，不得写入公开仓库，不得作为答案附件上传

**旁白续：**

> API Key 是个人调用凭证，仅限本人在本场比赛中使用。不得转发给其他选手，不得写入公开代码仓库，不得上传为答案附件，也不得在截图、日志或录屏中暴露。

**录制验收点：**

- API Key 必须逐帧检查并完整打码。
- 不在旁白中固定宣读模型数量，避免允许列表调整后视频失效。
- 模型 ID 可以展示演示值，但必须与录制页面一致。

### 镜头 09：在本地工具中配置接口

**建议时长：** 06:10 至 07:10

**画面操作：**

1. 切换到本地知识库或智能化工具的模型配置页。
2. 协议选择 OpenAI Chat Completions 兼容方式。
3. 将完整 API URL 粘贴到 Base URL 或模型服务地址字段。
4. 将 API Key 粘贴到凭证字段，字段内容保持隐藏。
5. 将刚才复制的准确模型 ID 粘贴到模型字段。
6. 保存配置。

**旁白：**

> 接下来在本地知识库或智能化工具中完成模型配置。接口统一使用 OpenAI Chat Completions 兼容规范。将系统页面提供的完整 API URL 填入 Base URL 或模型服务地址，将本人 API Key 填入凭证字段，再填写从可用模型列表中复制的准确模型 ID。不同工具的字段名称可能略有差异，但地址、凭证、模型三个要素必须对应正确。赛前测试和正式比赛使用相同的请求格式；正式比赛时，只需按照现场页面替换 API URL、API Key 和允许模型。

**错误示例特写：**

- API URL 后再次添加 `/v1`。
- 将网页登录密码填入 API Key 字段。
- 手工输入模型简称或改变模型 ID 大小写。

**旁白续：**

> 常见配置错误包括重复添加 `/v1`、把网页登录密码当作 API Key、使用模型简称，以及自行改变模型 ID 的大小写。出现调用失败时，应先逐项核对这三个位置。

**录制验收点：**

- 本地工具使用专门准备的演示配置页。
- 不露出真实密钥、历史请求、个人目录或无关服务地址。

### 镜头 10：完成最小调用和知识库联调

**建议时长：** 07:10 至 08:20

**画面操作：**

1. 回到 API 技术文档，短暂停留在“快速调用”和“接口地址”。
2. 展示 `GET /models` 和 `POST /chat/completions`。
3. 通过本地工具或页面提供的模型调用测试功能发送一条短文本请求。
4. 返回本地知识库，发起一次带资料检索的模拟问题。
5. 展示模型回答和引用来源。

**旁白：**

> 首次联调应从最小请求开始。先查询模型列表，确认当前账号能够读取允许模型；再发送一条简短的对话请求，确认地址、凭证和模型 ID 配置正确。随后回到本地知识库，测试一次完整的资料检索、上下文组织、模型调用和引用返回流程。仅仅收到模型回复，并不代表知识库已经准备完成，还应确认检索结果能够定位原文，并验证较长材料的处理是否稳定。

**屏幕文字：**

> 最小联调顺序<br>
> 查询模型 > 短文本调用 > 知识库检索 > 引用核验 > 长文本测试

**常见错误提示画面：**

> 401：检查 API Key<br>
> 400 model_not_allowed：检查模型 ID<br>
> 429：降低调用频率，稍后重试<br>
> 503 service_suspended：停止重复调用并报告

**旁白续：**

> 如接口返回四百零一，应检查 API Key 是否完整、是否属于当前账号；如返回模型不允许使用，应重新复制系统页面中的模型 ID；如返回四百二十九，应降低调用频率，等待后再重试。比赛模式可能不限制总调用次数，但页面显示的每分钟频率限制仍然有效。如持续返回服务暂停或其他异常，不要高频重复请求，应按照现场要求报告。

**录制验收点：**

- 测试问题使用模拟内容，不使用正式题目。
- 画面应同时体现“模型返回”和“引用来源”。

### 镜头 11：赛前完成一次答题全流程演练

**建议时长：** 08:20 至 09:00

**画面操作：**

- 在测试模式中依次演示打开题目、输入简短答案、插入一张演示图片、上传一个演示附件、保存草稿、确认“已保存”，最后对测试题执行最终提交。

**旁白：**

> API 联调完成后，还应在测试模式中完成一次答题全流程演练。至少测试题目读取、富文本输入、图片或附件上传、草稿保存、页面恢复和最终提交确认。点击“保存草稿”后，应等待页面明确显示“已保存”状态。测试题最终提交后同样会被锁定，这是用于帮助选手熟悉不可撤回的提交规则。

**录制验收点：**

- 使用测试题和演示附件。
- 演示最终提交时明确这是测试模式，不计入正式成绩。

**屏幕文字：**

> 仅连接组委会指定竞赛网络<br>
