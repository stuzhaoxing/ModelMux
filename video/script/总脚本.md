# 江苏省监测技能竞赛在线答题系统介绍视频脚本

全片分为 4 章，每章独立录制。本片重点介绍选手接入大模型和在线出题答题，技术端只作简要说明。

## 第一章：赛前、赛中与三个系统

### 镜头 1：系统登录页

旁白：

> 下面介绍江苏省监测技能竞赛在线答题系统。系统覆盖赛前测试和赛中正式使用两个阶段，为选手使用大模型和在线答题提供统一平台。

### 镜头 2：赛前测试与赛中正式环境

旁白：

> 赛前，选手获取个人凭证，把大模型 API 接入自己的知识库并完成调试。赛中，选手继续使用相同的接入方式，同时通过系统接收题目并完成作答。

### 镜头 3：三个使用端

旁白：

> 系统分为技术端、评委端和选手端。技术端负责基础保障，评委端负责出题和收卷，选手端负责接入大模型并在线作答。下面重点介绍选手使用和出题答题流程。

本章要点：

- 系统覆盖赛前接入调试和赛中正式使用。
- 领导重点关注选手使用和出题答题流程。

## 第二章：技术系统

### 镜头 1：创建账号

旁白：

> 技术端为评委和选手创建账号。选手获得账号的同时，也会获得大模型 API 接入凭证。

### 镜头 2：多路服务保障

旁白：

> 同一个模型由多路服务共同保障。其中一路不可用时，系统自动使用其他可用服务。这个过程不改变选手的使用方式，也不需要选手修改程序。

本章要点：

- 技术端只承担账号创建和模型服务保障。
- 服务变化不会影响选手的使用方式。

## 第三章：选手接入大模型 API

### 镜头 1：选手获取接入凭证

旁白：

> 接下来进入选手系统。选手登录后，可以获得自己的大模型 API 接入凭证，并查看允许使用的模型。

### 镜头 2：接入选手自己的知识库

旁白：

> 获取凭证后，选手就可以把大模型 API 接入自己的知识库或参赛程序，在自己的系统中使用大模型能力。

### 镜头 3：完成赛前调试

旁白：

> 选手在赛前完成接入和调试。进入赛中正式环境后，继续使用相同的接入方式，不需要临时修改程序。

本章要点：

- 选手获取自己的接入凭证。
- 大模型 API 可以接入选手自己的知识库或参赛程序。
- 赛前完成调试，赛中沿用相同的接入方式。

## 第四章：评委出题与选手答题

### 镜头 1：评委编辑并发布题目

旁白：

> 最后介绍在线出题和答题流程。先看评委系统。评委可以创建题目，编辑文字和图片，保存草稿，并在确认后正式发布。

### 镜头 2：切换到选手端，题目自动出现

旁白：

> 现在切换到选手系统。题目发布后，选手页面会自动出现新题目，不需要手动刷新。选手可以立即查看题目并开始作答。

### 镜头 3：选手作答并保存草稿

旁白：

> 作答内容支持文字和图片。答题过程中可以多次保存草稿，保存后仍然可以继续修改，避免因为误操作丢失已经填写的内容。

### 镜头 4：选手最终交卷

旁白：

> 答题完成后，选手点击最终交卷。交卷成功后，页面显示已提交状态，答案立即锁定。即使刷新页面，也不能再次编辑。

### 镜头 5：返回评委端查看答卷

旁白：

> 最后返回评委系统。评委页面会同步显示未开始、草稿中和已提交人数，并可以逐人查看完整答卷和提交时间。至此，系统完成了从评委发布题目、选手接收题目、在线作答、最终交卷到评委收卷的完整流程。

### 镜头 6：三个系统结果画面依次回顾

旁白：

> 通过技术系统、评委系统和选手系统，平台把模型服务管理、选手 API 接入和在线答题整合在一起。赛前，技术人员完成服务准备，选手把 API 接入自己的知识库并完成调试。赛中，技术端通过多路模型服务保障运行，评委完成出题和收卷，选手使用大模型并完成答题，形成完整的竞赛业务流程。

本章要点：

- 题目发布后，选手能够自动收到。
- 草稿可以修改，最终交卷后不可修改。
- 评委能够实时查看答题进度和完整答卷。
- 三个系统共同支撑完整竞赛流程。
