# ModelMux 大模型接口压力测试报告

- 测试时间：2026-09-03 19:48-19:58（Asia/Shanghai）
- 生产入口：`https://dbw.lic-inc.com/v1/chat/completions`
- 测试模型：`qwen3.7-flash`
- 上游：阿里云百炼（DashScope）
- 服务器：2 vCPU、3.4 GiB 内存、4.0 GiB Swap
- 结论：通过

## 1. 结论摘要

本次共执行 2,260 次真实模型调用，其中 2,256 次为统计样本、4 次为预热请求。所有统计样本均返回 HTTP 200，成功率 100%，全部命中阿里云上游；压测前后健康检查均为 `ok`，服务没有重启，也没有产生 warning 级别以上日志。

短文本场景下，20 并发持续 30 秒完成 1,649 次请求，吞吐 53.76 RPS，P50 311 ms、P95 518 ms、P99 986 ms。50 和 100 并发突发请求也全部成功，但长尾分别增长到约 7.2 秒和 7.8 秒。因此，当前机器可把“20 个同时活跃的短回答请求”作为较稳妥的运行基线；50/100 并发可视为成功承受的突发压力，不应直接作为延迟承诺。

Base64 经“流式解码到临时文件 -> OSS 单对象上传 -> URL 改写 -> 上游模型”链路验证通过。约 150 KiB 请求体在 20 并发下 40/40 成功；约 9.77 MiB 请求体在 5 并发下 10/10 成功。大包测试没有触发 Swap、OOM、服务重启或临时文件残留，但 5 并发大包的 P50 已升至 14.86 秒，网关进程平均使用约 89% 的单核算力，说明该改造控制住了内存放大，不能消除 Base64 解码、哈希、磁盘写入、OSS 上传和公网传输的 CPU/时间成本。

## 2. 模型和成本

选择 `qwen3.7-flash` 是为了用较低成本覆盖真实生产链路。按阿里云百炼北京地域、输入不超过 32K Token 的[官方价格](https://help.aliyun.com/zh/model-studio/qwen3-7-flash)估算：

| 项目 | 单价 |
| --- | ---: |
| 输入 | ¥0.20 / 百万 Token |
| 输出 | ¥0.80 / 百万 Token |

统计样本合计使用 101,438 输入 Token、4,507 输出 Token，共 105,945 Token，估算费用约 **¥0.0239**。4 次预热请求未计入，实际总费用仍低于约 ¥0.025。

压测前实时查询到该账号的 Flash 配额为 3,000 次 / 6 秒和 5,000,000 Token / 60 秒。该值是账号配额，不是网关已经证明可持续承载的并发数；本报告以实测结果作为容量依据。

## 3. 测试方法

请求从本地测试机经公网 HTTPS、Nginx、ModelMux 生产网关到阿里云模型，报告中的延迟包含公网、TLS、网关处理和上游推理时间。

文本请求参数：

- 非流式请求，提示词只要求回复 `OK`
- `enable_thinking=false`
- `max_tokens=4`
- `temperature=0`
- 30 秒单请求超时
- 阶梯并发后追加 20 并发、30 秒持续测试

图片请求沿用相同生成参数。小图采用 115,168 字节的真实 PNG，请求体 153,832 字节；大图采用 1,600 x 1,600 的有效 PNG，原文件 7,682,833 字节，请求体 10,244,055 字节（约 9.77 MiB），单请求超时 120 秒。

## 7. 容量判断与建议

1. 当前生产配置可支撑 20 个同时活跃的短文本请求，实测稳态吞吐约 53.76 RPS。实际回答更长时，上游生成时间会变长，吞吐会低于本次结果。
2. 50/100 并发突发没有失败，但 P99 已达到 7 秒以上。建议把它们看作生存测试，不作为业务延迟目标。
3. Base64 改写有效降低了内存风险，大包并发没有触发 Swap，RSS 也没有随请求总体积线性增长。Swap 可作为 OOM 的最后缓冲，但不能解决大包带来的 CPU 高占用和长延迟。
4. 对接近 10 MiB 的 Base64，请预期单请求 6-16 秒；当前 2 vCPU 机器不宜把大包场景按 20 并发常态运行。按本次结果，5 并发是已经验证的安全范围，超过该值应单独逐级复测。
5. 建议监控并告警：接口 5xx/超时率、P95/P99、进程 CPU、可用内存、Swap 使用量、OSS 上传失败和临时目录残留。CPU 连续接近两核上限时，加 Swap 不会改善卡顿，应扩容 CPU 或把文件处理拆到独立上传服务。

## 8. 边界说明

本次测试验证的是短输出、非流式 Chat Completions，以及图片 Base64 经 OSS 改写后的链路。它不代表长文本生成、超长上下文、流式连接长时间占用、音视频/PDF 大文件或阿里云账号配额极限。若赛事实际请求包含这些模式，需要按真实提示词长度、输出长度和文件分布另做场景化压测。
