# 答题重置与历史归档

比赛流程固定为：**测试 → 开始比赛 → 比赛中 → 倒计时归零或立即结束比赛 → 比赛已结束 → 归档并重置 → 测试**。结束后不能直接重新开始，后台接口也会拒绝，必须先归档并重置。测试状态下仍可归档并重置测试数据。

大屏的赛前提醒仅在测试状态展示，比赛中和比赛已结束时均隐藏。归档并重置回到测试后，会再次展示已保存的赛前公告。

管理员进入「考务总览」，结束状态的「前往归档并重置」会定位到页面下方的「答题重置与历史归档」。点击「归档并重置」，输入同样的确认文字后执行。比赛中禁止重置或恢复，需要先结束比赛。

重置覆盖全部选手、测试题和正式赛题，不受页面上的阶段筛选影响：

- 归档并清空服务器已保存的草稿、已提交答卷、答题动态日志和比赛 Token 统计。
- 清空开始／结束时间，回到不限时的测试状态，保留配置的比赛时长。比赛当天点击「开始比赛」。
- 保留题目内容及状态、选手账号、密码、API Key、登录会话、附件文件，以及登录／题目管理等审计日志。

归档与清理在同一个 InnoDB 事务中完成，任一步失败都会回滚。重复提交同一轮重置不会清理下一轮数据。每次重置或恢复会递增答题轮次，旧页面的保存／提交请求会被拒绝；浏览器本机草稿按轮次隔离，不会自动带入下一轮。尚未保存到服务器的编辑内容无法纳入服务端归档，旧的本机缓存仍留在对应旧轮次下。

## 恢复与下载

历史归档显示时间、选手账号数、答卷数和已提交数。点击「恢复」，输入「恢复归档」后，将恢复对应答卷的内容、草稿／提交状态、原保存时间、答题日志和 Token 统计。恢复前会自动将当前数据另存为一份「恢复前备份」。恢复不改变当前测试／比赛模式、比赛状态、时长和计时设置。归档中的历史比赛时间仅保留在归档中，不写回当前比赛。

恢复不覆盖当前题目和账号。如果归档答卷对应的题目内容已更改、账号已删除，或归档附件记录已缺失，会拒绝恢复并保持当前数据不变。仍可下载归档核对原始内容。

下载文件为 JSON，包括答卷、当时的题目内容、选手身份、统计和附件索引，不包含账号密码或 API Key。附件本体保留在服务器，不打包进 JSON。归档保存在当前 MySQL 数据库中，服务器备份时需同时保留数据库与附件目录。

## 验证

`pnpm test` 包括鉴权、来源校验、确认文字及本机草稿轮次隔离的测试。

真实 MySQL 集成测试需显式设置 `MODELMUX_ARCHIVE_TEST_URL`，该连接应有创建临时数据库的权限，然后运行：

```sh
pnpm exec vitest run lib/competition/archives.integration.test.ts
```

测试会新建随机命名的 `modelmux_reset_test_*` 数据库，结束后删除该临时库，不在连接字符串原有的比赛库中写入测试数据。覆盖完整归档／恢复、失败回滚、并发重置、旧页面保存拦截，以及清理后重新开始正式比赛。
